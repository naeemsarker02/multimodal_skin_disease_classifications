# ISIC Archive 2 Processed Dataset Description

Generated: 2026-07-08 00:11:16

## Source

Raw data: `data/raw/ISIC_Archive_2/` (untouched, read-only).
Images are **not copied**; `image_path` points back to the original file under `data/raw/ISIC_Archive_2/images/`.

## Schema

Renamed for the unified cross-dataset schema: `isic_id`->`image_id`. Added: `image_path`, `dataset_source`, `disease_label`.

## Label Standardization

`diagnosis_3` (the finest diagnosis level populated for nearly all rows) is mapped to the shared ISIC canonical taxonomy (`src/data_cleaning/common_label_mapping.py`), used identically by ISIC Archive 1 so diseases common to both use identical names. See `label_mapping.csv`.

255 rows (1.01% of the raw metadata) have no `diagnosis_3` value and therefore no `disease_label` - they are excluded from the train/val/test split since `diagnosis_1`/`diagnosis_2` alone are too coarse for this project's multi-class target.

## Value Validation

No implausible values were flagged.

## Train / Validation / Test Split

- Method: group-wise split, where the group is `lesion_id` when present (93.4% of labeled rows) and falls back to the row's own `image_id` as a singleton group otherwise (mirroring HAM10000's lesion-wise approach, extended for the mixed identifier coverage here). Stratified by each group's `disease_label` - the audit confirmed 0 groups have inconsistent labels.
- Note: `patient_id` is populated for only 417/25,331 rows, so a true patient-wise split is not possible for the bulk of this archive.
- Target ratios: {'train': 0.7, 'val': 0.15, 'test': 0.15}
- Random seed: 42 (fixed, for reproducibility)
- Total images (labeled, post-exclusion): 25076

- **train**: 17535 images
- **val**: 3769 images
- **test**: 3772 images

No lesion/image group appears in more than one split (verified in `split_quality_report.csv`).

## Cross-Dataset External-Validation Exclusions (2026-07-08)

`docs/Dataset_Preparation_Final_Report.md` §6 found that this archive shares
9,873 images with HAM10000 (98.6% of HAM10000's total) — HAM10000 is
essentially a subset of this archive's underlying image pool. Since 46% of
those shared images land in different train/val/test splits between the two
datasets when split independently, using this archive in full as "external
validation" against a HAM10000-trained model would silently include images
the model already saw in training.

**Decision (fix (b) — restrict external-validation claims, see
`Project_Tracking.md` for full rationale):** rather than re-splitting all
three datasets globally, the 9,873 overlapping `image_id`s are excluded from
this archive whenever it is used as external validation against a
HAM10000-trained model. This archive's own train/val/test files
(`metadata_train.csv`, `metadata_val.csv`, `metadata_test.csv`) and split
ratios are **unchanged** — the exclusion applies only at evaluation time, via
`data/processed/ISIC_Archive_2/external_validation_exclusions.csv` (the list
of excluded `image_id`s, generated by
`src/data_cleaning/cross_dataset_leakage_filter.py`).

Row counts:

| | Count |
|---|---|
| Total images in this archive | 25,076 |
| Overlapping with HAM10000 (excluded before HAM10000-external-validation use) | 9,873 |
| Remaining, valid for external validation against a HAM10000-trained model | 15,203 |

This exclusion is **not needed** when this archive is used for its own
internal train/val/test evaluation, or as external validation against a
model trained only on PAD-UFES-20 (which has zero image overlap with any
other dataset).

**Also documented (no action needed):** of the 1,673 images this archive
shares with ISIC Archive 1, 3 have disagreeing `disease_label` values between
the two archives (`ISIC_0028619`: Actinic Keratosis here vs. Nevus in Archive
1; `ISIC_0011126` and `ISIC_0011118`: Melanoma here vs. Seborrheic Keratosis
in Archive 1). This is a pre-existing annotation disagreement inherited from
the source archives, not introduced by this project's cleaning. Negligible
volume (0.18% of the shared images); keep in mind if these specific images
are ever used in a merged evaluation pool.

## Known Limitations

- Severe class imbalance: Nevus (~51%) vs. two classes with only 1 image each (Epidermal Nevus, Atypical Melanocytic Neoplasm - both folded into Nevus, see label_mapping.csv).
- `patient_id` populated for <2% of rows - cannot control for patient-level leakage across splits beyond the lesion_id grouping used.
- `anatom_site_4`, `anatom_site_5`, `family_hx_mm`, `personal_hx_mm`, `clin_size_long_diam_mm` are >96% missing by design (deep hierarchy levels / rarely-recorded clinical fields), not a data defect.
